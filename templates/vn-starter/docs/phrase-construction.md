## Content contract

Add a `phrase_construction` event with a complete scene presentation and an `exercise`:

- `id`, `title`, `characterId`, `question`, `pinyin`, `translation`, and `goal` supply the task. Optional `showQuestion` defaults to true: omission preserves the existing character/question/pinyin/translation header. Explicit false omits that entire header from visible and accessible content and permits empty `characterId`/`question`; `goal` must still be nonempty and remains visible.
- `slots` define two to eight meaningful positions. Each has a unique semantic `role` and a visible `label`. Roles are arbitrary strings, such as `intent`, `drink`, and `modifier`, or `time`, `subject`, `activity`, and `question`.
- `tiles` provide an ID, Chinese `text`, required nonblank English `meaning`, and one slot `role`. Required nonblank `pinyin` appears in the bank, occupied slots and accessible add/remove labels. Required `audioId` and `speakerId` bind the exact Chinese utterance to a recorded voice in `speechRegistry.ts`; chapter loading validates text/speaker identity and production builds validate actual files/provenance. The seven coffee tiles now require Emma’s assigned identity; the frozen null-speaker allowances describe historical files only. Multiple tiles with the same role create plausible alternatives.
- `modelTileIds` provide a complete grammatical example for missing-role coaching.
- Optional `requestTileId` distinguishes a request from a statement or preference. Omit it in interactions without that distinction.
- `coaching.structure` and `coaching.request` each supply a character line and actionable explanation. Teaching stays inside the scene, without an incorrect-answer screen.
- `outcomes` enumerate each accepted combination by ordered `tileIds`, unique `id`, `targetEventId`, and `effects`. An optional `assistedTargetEventId` sends helped players to a different response.
- Optional `actionLabels: { submit, help }` supplies context-appropriate action text. Omission preserves the shipped coffee labels. Chapter three uses “Say it” and “Help” for the examiner interaction.
- Every phrase builder initially hides tile translations and always renders the shared Show meanings / Hide meanings control. Authors must supply a nonblank `meaning` for every tile and cannot disable lookup or show translations upfront. Omit `showMeanings` in new content. The deprecated `showMeanings?: false` field accepts existing shipped false values for compatibility only; true is rejected by the schema and the component never reads this field. `showSlotLabels` independently defaults to true; false hides the visible slot labels.

The schema checks tile/role identity, grammatical model sequences, all destination event IDs, duplicate outcomes, and complete coverage of every valid combination. This is authored phrase matching, not free-text Chinese parsing. A role identifies a position in the intended sentence pattern.

## Player interaction

`phraseTileOrder.ts` supplies the bank’s actual DOM order using a versioned `phrase-bank-order-v1|<exercise.id>` FNV32/Fisher–Yates seed. The order is stable across actions, audio, lookup, Help, pause, reload, replay and viewports; responsive columns wrap that same DOM sequence. Placed tiles remain disabled in place, with independent speaker controls. Canonical tile arrays, sentence slots, drag/audio IDs and saved drafts remain unchanged.

The bank must not display the complete model or any accepted outcome contiguously in row-major reading order. A single seeded shuffle is tried first, then its successive left rotations; if necessary a stable descending slot-role sort preserves seeded order within each role. Noncontiguous subsequences are allowed. The current distinct-role schema permits a safe order; an unsupported future case keeps deterministic display and logs its limitation instead of failing the UI. Help still repairs authored roles while retaining the learner’s selected meaning, including all six coffee alternatives; it never reads the displayed bank as a model.

The [Chapter Ten playtest amendment](../production/chapter-10/revisions/playtest-01/director-addendum.md) introduced this shared rule for the seven builders installed then: Two, Three, Six, Seven, Eight, Nine and Ten. Eleven, Twelve and Thirteen use the same rule as the eighth, ninth and tenth builders. `phraseTileOrder.test.ts` covers exact-ID stability, accepted alternatives and fallback; `phraseTileOrder.spec.ts` covers actual DOM/keyboard/tap/drag, meaning/audio controls, saved coaching and Help across all ten installed builders.

Dragging from the bank places a tile in the chosen slot. Dragging between occupied slots swaps them. Tapping or pressing Enter on a bank tile fills the first empty slot; activating a placed tile removes it. The same component supports different slot counts and wraps longer constructions on phones.

When meanings start hidden, the player can reveal or hide them together with a button that supports mouse, touch, and keyboard. This applies to both the bank and placed tiles; hidden meanings are also omitted from hover titles and accessible labels. Lookup does not change the sentence, rewards, or coaching history. It is temporary UI state and resets when the panel closes or a different exercise opens. The coffee scene uses this mode while retaining its three labeled slots.

`PronunciationButton` gives every tile separate sibling controls in the bank and occupied slot; buttons are never nested inside the tile edit/remove control. Both share the tile identity, and the bank speaker stays enabled after placement. Listening never places/removes a tile, reveals its meaning, or changes learning progress. A second tap stops the active clip; another speaker replaces it. `game/audio/usePhraseAudio.ts` delegates these recordings to `useRecordedPronunciation.ts`, shared with vocabulary review, in React and releases them on completion, mute, pause, hidden-tab pause, submission, replay, or navigation. The Say action stops pronunciation synchronously before story voice entry. Playback errors offer another tap to retry; a stale failure from a replaced clip cannot stop the current clip. Home-navigation checks wait for the committed Home view and scene unmount before asserting source release. No browser-generated voice is substituted for a supplied recording. On phones, audio cards use two columns to preserve separate 44px listen targets; the panel scrolls to keep every choice reachable.

The Say action stays disabled until all slots are filled. Mixed-up role order prompts a retry; the character's help rearranges the player's existing choices and fills missing roles from the model. A valid sentence with unintended meaning follows its authored consequence. Help never silently replaces a selected drink or other meaningful alternative just to match the goal.

## Coffee behavior

The seven supplied tiles produce six valid orders. The iced latte without sugar awards 10 Mandarin XP; the other five combinations award 5. Hot, extra-sugar, no-ice, and combined variations each have a matching response. An immediate correct order reaches “Then perfect”; a helped correct order reaches “说得不错.” Each finished response grants one Kai trust, in addition to `kai-probably`’s Trust +1 and Affection +1; the response endings gain no additional Affection.

`MandarinXP` tracks exercise experience separately from the original `Mandarin` story attribute. Rewards are explicit story effects, so future exercises can use their own values.
